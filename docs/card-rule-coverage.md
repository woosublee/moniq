# 카드 규칙 커버리지

## 운영 적용과 조건 모델은 다릅니다

두 상품 모두 **공식 설명서 확보 / 일부 조건 모델 구현 / 효력 기간 미검증 / 실사용 자동 계산 대기**입니다. `candidatePackSchema` 검증 성공은 정책 발행 승인이 아닙니다. 출시일·심의일·파일명·문서 ID·메타데이터 날짜를 효력일로 사용하지 않습니다.

카탈로그 후보는 기존 `CardPolicy`와 의도적으로 호환되지 않습니다. 공식 정률은 분자·분모와 `rounding: unverified`로 보관합니다. 정수 결과만 쓰는 synthetic fixture의 실행 어댑터는 `catalog-replay.test.ts` 안에만 있습니다. 테스트 기간 `[2026-01-01, 2026-04-01)`과 테스트의 verified/published 표시는 공식 상품 유효기간이나 실사용 판본이 아닙니다.

`20260913103000_verified_card_policies.sql`은 파일명과 달리 **공개 cards 메타데이터만 추가**합니다. `card_rule_versions` 등 실행 규칙 및 보유/원장/계정은 생성·변경하지 않습니다. 기존 정확 상품이 있으면 새 cards 행도 만들지 않습니다. 이 SQL은 실행 검증되지 않았습니다.

### 주유 한도 조사 판정의 갱신

이전 연구의 텍스트 표 평탄화는 주유 행의 독립 한도 수치를 놓쳤습니다. **실제 PDF p.1을 이미지로 직접 보면 대중교통/택시 행과 주유 행 사이의 선은 할인한도 열을 가로지르지 않으며, 1만원/1만5천원 셀이 두 행을 병합합니다.** 따라서 이 정확한 PDF에서는 두 영역의 **할인금액 합산** 한도가 확인됩니다. 주유의 독립 한도나 주유 사용금액 cap이 아닙니다. 기존 연구 문서는 덮어쓰지 않습니다.

테스트 예시는 synthetic 확정 주유 할인 소비 7,000원 → 40만원 구간 10,000원 cap의 잔여 3,000원 → 택시 사용액 50,000원의 10% 산술액 5,000원 중 3,000원만 적용입니다. 이 7,000원은 주유 지출이 아니며 고시가를 추정해 계산한 값도 아닙니다. 버스/지하철 명세서 이용일 귀속 및 주유 환산은 미구현입니다.

p.2 실적에서는 Trendy 서비스 받은 매출 전체만 혜택 의존 제외입니다. Daily 거래가 항상 실적에 포함된다는 역규칙은 만들지 않습니다. 다른 실적 제외가 있으면 별도로 제외해야 합니다.

## 공통 전월 실적과 입력 계약

전월 1일~말일 국내 승인금액 기준. 해외는 매입 완료 기준이지만 실행 모델 범위 밖입니다. 현금서비스/카드론, 세금·공과금, 아파트관리비, 정부지원금, 대학/대학원 등록금, 수수료·이자·연체료·연회비, 상품권·선불 구입/충전, 무승인 전표 및 취소금액이 실적 제외로 명시되어 있습니다. 취소 세부 자동 규칙은 별도이며 `cancellation: {kind: unknown}`을 유지합니다.

후보의 `*_eligible`은 사용자가 입력한 업종이나 KB 공식 MCC가 **아닙니다**. 제외 품목·결제 경로·승인 업종·무이자 여부·실적 제외 비해당을 독립적으로 대조했다고 가정하는 synthetic 정규화 사실입니다. 전기/수도용 `*_performance_excluded`는 실적 제외에 해당함을 별도로 확인한 결합 사실입니다. 실제 거래를 이런 분류로 바꾸는 운영 매퍼는 만들지 않았습니다. 이 전제를 숨기고 정책으로 승격하면 안 됩니다.

본인회원 기준 한도라는 문구에서 가족카드 합산/공유를 추정하지 않습니다. 모델의 self binding은 단일 카드 fixture 전제일 뿐입니다. 같은 카드 서비스 그룹의 pool 공유와 여러 카드 실물의 가족 공유는 다릅니다.

## Synthetic 검증 예시와 미지원

- 실적 399,999 → 혜택 미달, 400,000 → 1구간, 799,999 → 1구간, 800,000 → 2구간.
- Biz Favorite 9,999 → 0P, 10,000 → 1,500P. Miz 커피 19,999 → 0원, 20,000 → 2,000원.
- 각 그룹 누적 소비·한도 소진·독립 pool, Favorite/Trendy 매출 전체 실적 제외, Daily 별도 실적 포함 사례.
- 자료가 없는 전월/월 초 소비량, unknown 환불 정책, 후보/미검증 판본은 0 또는 전체 지원으로 승격하지 않음.
- 포인트리 15,000P는 별도 프로그램 합계로 표시하며 원화 전용 `benefitAmount`에 더하지 않음.
- 후보를 운영 strict `cardPolicySchema`에 넘기면 거절. 후보 검증 내부 구조용 fixed-zero placeholder는 외부 반환/SQL 저장하지 않음.

**미지원/미검증:** 효력기간, 절사/반올림, 실가맹점/업종/PG/임대/입점/상품권 판정, 해외 환산·매입일, 할부·무이자 상세, 신규 유예 자동 판단, 가족 실적/한도, 부분/익월 환불·복원·소급, Biz 매입 순서가 승인 순서와 다른 경우, 버스/지하철 청구 이용일, 고시 유가/리터 환산, 티타늄/여행/MyBiz 비금전 서비스. 전월 자료/목표의 실제 폼은 Task7, 3탭 UI는 Task6 범위입니다.
